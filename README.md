## 📖 О проблеме и решении

Рынки предсказаний (Prediction Markets), такие как **Polymarket** и **Kalshi**, предлагают ставки на одни и те же мировые события (выборы, крипта, экономика). Из-за разницы в ликвидности между биржами часто возникают **арбитражные ситуации (вилки)** — возможность сделать ставку на противоположные исходы на разных биржах и получить 100% гарантированную прибыль независимо от исхода события.

**Главная проблема:** Биржи формулируют вопросы по-разному. 
*   *Polymarket:* "Will Donald Trump win the 2024 Presidential Election?"
*   *Kalshi:* "Who will be the next US President? (Donald Trump)"

Обычные сканеры, использующие парсинг строк или регулярные выражения, здесь бессильны. Они пропускают 90% вилок. 

**Мое решение:** Использование **Двойной AI-Архитектуры (Dual AI Engine)**, которая понимает семантический смысл вопросов, сопоставляет их и математически доказывает наличие вилки.

## 🧠 Архитектура Dual-AI (Как работают две нейросети)

Чтобы система работала быстро и не тратила сотни долларов на API-запросы к LLM, я разработал двухступенчатый пайплайн фильтрации.

### 🤖 AI #1: Локальный векторный поиск (The Sprinter)
Использовать мощную LLM для сравнения 5000 рынков Polymarket с 5000 рынками Kalshi (25 миллионов комбинаций) — безумие. Поэтому на первом этапе работает локальная NLP-модель.
*   **Технология:** `sentence-transformers` (модель `all-MiniLM-L6-v2`).
*   **Как работает:** Все вопросы с Kalshi прогоняются через модель и превращаются в многомерные векторы (эмбеддинги). Затем вопросы с Polymarket также векторизуются.
*   **Математика:** С помощью вычисления **косинусного сходства (Cosine Similarity)** алгоритм мгновенно находит пары, которые семантически похожи (например, сходство > 63%).
*   **Результат:** Из 25,000,000 возможных комбинаций алгоритм за пару секунд оставляет около 100-200 самых вероятных кандидатов. Это абсолютно бесплатно и работает на CPU.

### 🧠 AI #2: Облачная LLM Верификация (The Judge)
Векторные модели глупы в логике. Для них фразы *"Биткоин упадет до $60k"* и *"Биткоин упадет до $58k"* выглядят одинаково (сходство 99%), но для арбитража это фатальная ошибка. Здесь вступает в игру **DeepSeek API**.
*   **Технология:** DeepSeek Chat API (с обходом SSL-ошибок через кастомный `aiohttp` коннектор).
*   **Батчинг (Batching):** Чтобы не упереться в Rate Limits (429 ошибка), кандидаты упаковываются в "пачки" (batches) по 15 пар и отправляются асинхронно.
*   **Промпт-инжиниринг:** Нейросети задаются строгие правила (Contextual Rules). Она проверяет таймфреймы, логические подмножества (например, "DHS shutdown" не равно "Government shutdown") и точные имена.
*   **Двойная верификация (Double Verification):** Чтобы исключить галлюцинации LLM, пары, которые DeepSeek пометил как "Совпадение", отправляются на повторную проверку (Этап 2). Только пары, прошедшие обе проверки, допускаются к расчету денег.

## ⚙️ Полный алгоритм работы системы (Step-by-Step)

1.  **Асинхронный Scraping (`module_polymarket.py`, `module_kalshi.py`):**
    *   Используется `httpx` с поддержкой HTTP/2.
    *   Динамическое распределение лимитов: скрипт сначала опрашивает API бирж на количество доступных рынков в каждой категории (`crypto`, `politics` и т.д.), а затем пропорционально распределяет заданный лимит (например, 5000 рынков), чтобы собрать максимально релевантную базу.
2.  **Пре-фильтрация и Категоризация (`categories.py`):**
    *   Написан огромный модуль (более 1000 строк), который с помощью словарей ключевых слов жестко классифицирует каждый рынок. Это не дает алгоритму сравнивать выборы в США с ценой Ethereum, экономя вычислительные ресурсы.
3.  **Нормализация текста:**
    *   Удаление спецсимволов, приведение чисел к единому формату (например, "10k" -> "10000").
4.  **AI Matching (Описано выше).**
5.  **Математика Арбитража (`module_arbitrage.py`):**
    *   Извлекаются цены (вероятности) исходов `Yes` и `No`.
    *   Рассчитываются коэффициенты: $K = \frac{1}{Price}$.
    *   Рассчитывается сумма вероятностей (Sp) для кросс-ставок: $Sp = \frac{1}{K_{poly}} + \frac{1}{K_{kalshi}}$.
    *   Если $Sp < 1$, рассчитывается чистая доходность: $Profit = (1 - Sp) \times 100$.
    *   Рассчитываются точные суммы ставок (Stakes) по формуле: $Stake = \frac{Bankroll}{K \times Sp}$.
6.  **Сохранение в БД (`database.py`):**
    *   Используется асинхронная `SQLAlchemy` + `aiosqlite`. Данные сохраняются в формате JSON для удобной отдачи на Frontend.
7.  **Live Reparse (Режим реального времени):**
    *   Пользователь в UI может нажать кнопку "Auto-Update". Бэкенд берет уже найденные пары и делает точечные запросы к API бирж по их уникальным `slug` / `ticker`, мгновенно пересчитывая профит без необходимости запускать тяжелый AI-скан заново.

## 🛠️ Технологический стек

### Backend (Python)
*   **FastAPI** — Высокопроизводительный веб-фреймворк для создания API.
*   **Asyncio & HTTPX** — Для полностью асинхронного парсинга и сетевых запросов.
*   **Sentence-Transformers & NumPy** — Для создания эмбеддингов и вычисления косинусного сходства.
*   **SQLAlchemy (Async) & SQLite** — ORM для работы с базой данных.
*   **AIOHTTP** — Используется специально для обхода специфичных SSL-ошибок при работе с API DeepSeek.
*   **Colorama & Logging** — Для красивого и информативного вывода в консоль.

### Frontend (React)
*   **React 18** — Основная библиотека.
*   **Tailwind CSS** — Для создания сложного Cyberpunk-дизайна (Glassmorphism, неоновые тени).
*   **Framer Motion** — Для плавных анимаций появления элементов, графиков и счетчиков (60 FPS).
*   **ApexCharts** — Для рендеринга радиальных графиков нагрузки системы (CPU, RAM, Disk).
*   **Lucide React** — Векторные иконки.

## 📂 Структура проекта (Что внутри файлов)

*   `main_api.py` — Сердце бэкенда. REST API эндпоинты, управление фоновыми задачами (BackgroundTasks), отдача логов и системной статистики (psutil).
*   `scanner_engine.py` — Оркестратор. Связывает парсеры, AI и математику воедино. Управляет статусами сессий сканирования.
*   `module_matcher.py` — Тот самый **Dual-AI Engine**. Содержит классы `HybridMatcher` (локальные векторы) и `DeepSeekBatchVerifier` (асинхронные запросы к LLM с защитой от rate-limits).
*   `module_arbitrage.py` — Математическое ядро. Парсинг дат (ISO и Unix), расчет вилок, защита от деления на ноль.
*   `module_polymarket.py` & `module_kalshi.py` — Аппараты для взаимодействия с недокументированными API бирж. Поддержка пагинации, курсоров и прокси.
*   `categories.py` — Огромный эвристический анализатор текста для первичной сортировки рынков.
*   `database.py` — Схемы таблиц (Settings, ScanSession, Deal) и инициализация БД.
*   `App.jsx` (Frontend) — Монолитный, но круто структурированный React-компонент. Включает кастомные хуки для анимации чисел (`useSmoothProgress`), логику поллинга статуса и сложную систему локальных фильтров.
